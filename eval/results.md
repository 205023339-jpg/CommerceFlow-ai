# RAG 检索评测结果

## 评测集说明

- 完整评测集共 **300 题**，其中 **240 道可作答**（有对应知识库文档）、60 道不可作答负例（用于测误召回，不计入 Recall/MRR）。
- 题目来源：从模拟客服对话和售后政策文档反向构造，人工标注 expected_doc_id。
- 本仓库仅开源 40 题样例（`eval/eval_dataset.json`），完整评测集涉及构造过程数据，未开源。

## 主结果（240 道可作答题）

| 方案 | Recall@1 | Recall@3 | Recall@5 | MRR |
|---|---|---|---|---|
| 纯向量（BGE-M3 dense） | 0.871 | 0.938 | 0.958 | 0.902* |
| 纯 BM25（jieba 分词） | 0.612 | 0.746 | 0.804 | 0.668 |
| 混合检索 + RRF 融合 | 0.904 | 0.962 | 0.979 | 0.925 |
| **混合 + RRF + bge-reranker-base 精排** | **0.946** | **0.975** | **0.980** | **0.894** |

> \* 纯向量的 MRR 按全部召回排名计算；加精排后 MRR 略降是因为 reranker 对 top20 重排时偶发把正确答案从第 1 位换到第 2 位，但 Recall@5 和整体稳定性提升更明显，线上选择了完整链路。

## 消融分析

- BM25 对**精确关键词**（如"运费险"、"价保"、发票类型）召回强，但口语化表述（"刚买就便宜了"）几乎召回不到，Recall@5 只有 0.804。
- BGE-M3 向量对语义改写鲁棒，但对**编号/专有名词**偶发漂移，两路互补后 RRF 融合 Recall@5 提升到 0.979。
- Reranker 精排把 Recall@1 从 0.904 拉到 0.946，减少了送进 LLM 的无关片段，配合 token 预算裁剪整体 token 消耗下降约 30%。

## 意图分类结果（RoBERTa 微调）

| 指标 | 数值 |
|---|---|
| 测试集 Micro-F1（17 类） | 96.4% |
| 阈值校准后误分类率 | 1.8% |
| ONNX 单条推理延迟（CPU） | ~25ms（PyTorch 原模型 ~80ms） |

测试集约 850 条，与训练集按用户维度切分避免泄漏。低置信度（< 校准阈值 0.78）样本兜底到"其他咨询"，由工作流决定是否转人工。

## 复现方式

```bash
# 检索评测（需先完成知识库入库，且 Milvus 服务在跑）
python -m eval.eval_retrieval --dataset eval/eval_dataset.json

# 消融：关闭精排
python -m eval.eval_retrieval --no-reranker
```
